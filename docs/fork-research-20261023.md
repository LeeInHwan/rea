# REA 포크 및 확장 도구 조사 — 2026-10-23

## 판단

현재 용도인 macOS 앱·DMG, Windows 설치 폴더, APK 분석에는 공식 REA 최신
배포판에 개인 경로 검사 기능을 유지하는 구성이 적합하다. 실제로 기능을 크게
확장한 포크는 있으나, 조사 범위에서 기존 구성을 전면 교체할 만큼 검증된
우위는 확인하지 못했다. 아래 평가는 Git 이력·소스·공개 CI 확인에 근거하며
외부 포크의 실제 엔진을 이 Mac에서 실행한 성능 비교는 아니다.

## 조사 방법과 기준점

- GitHub API의 별점 순 상위 포크 40개를 가져와 각 기본 브랜치를 실제로 fetch했다.
- 공식 `main`의 `86655eac66555aaf4cbe500797d34071077a396a`와 Git 도달 가능
  커밋을 비교했다. 기본 브랜치 밖의 실험 브랜치, 모든 포크, 과거 squash로
  원본에 반영된 개별 기여까지 전수 조사한 결과는 아니다.
- 37개는 원본에 없는 커밋이 0개였다. 2개는 작업 지침 또는 TODO 주석만
  추가했으며, 1개는 실질적인 기능 확장을 포함했다. 원본에 커밋이 포함돼 있다는
  사실만으로 기여자의 다른 브랜치나 과거 기여가 없다고 판단하지 않는다.
- 별도로 검색한 관련 프로젝트는 GitHub의 `fork`, `parent`, 패키지 의존성과
  실제 구현을 확인해 포크·별도 확장·독립 도구로 구분했다.
- 공식 최신 GitHub release와 npm `latest`는 모두
  [6.7.0](https://github.com/morluto/rea/releases/tag/rea-agents-6.7.0)이었다.
  해당 태그는 `27dc42d10249f0410904a75c0997842eb03b931c`이고 조사 시점의
  개발 `main`은 그보다 595커밋 앞섰다. 이번 업데이트는 배포판 기준이다.

## RE-Agent를 자세히 본 결과

이름만 바꾼 저장소가 아니다. 다음은 실제 변경과 코드다.

- [함수 재구현 순서](https://github.com/heaven-hm/re-agent/commit/249383a84):
  호출 관계를 순환 그룹으로 묶고 함수 수·재시도 예산을 적용한다.
  `src/domain/reconstructionSchedule.ts`는 대상 해시·근거 ID·미해결 의존성을
  유지한다. 작업 계획 기능이며 그 자체로 함수 복구 성공을 증명하지 않는다.
- [체크포인트의 앱 그래프 보존](https://github.com/heaven-hm/re-agent/commit/a84c61e8b):
  실행 파일과 관련 앱 아티팩트의 연결을 명시하고 분석 재개 시 정체성을 확인한다.
- [Binary Ninja 제공자](https://github.com/heaven-hm/re-agent/commit/2677f1310):
  연결 설정·도구 실행·세션·doctor·테스트가 실제로 추가돼 있다.
  설정 검사 통과와 실제 엔진 연결 성공은 별개다. 이 Mac에서 Binary Ninja를
  설치하거나 해당 제공자를 검증하지 않았다.
- [최근 CI](https://github.com/heaven-hm/re-agent/actions/runs/39833369775)는
  정적 검사와 빌드 단계에서 실패했고, 후속 엔진/플랫폼 작업은 다수 건너뛰었다.
  빌드 실패 단계에는 캐시 재사용도 있으므로 모든 실패를 코드 결함으로
  단정하지 않는다. 다만 현재 검증 완료된 배포 후보로 취급할 수는 없다.
- README는 완전한 레거시 앱 이식 사례와 범용 동등성 검증이 아직 없다고
  명시한다. 저장소의 벤치마크와 일반적인 앱 복구 능력은 구분해야 한다.

## 고도화 우선순위

1. **분석 재개와 증거 보존:** 큰 앱을 나눠 조사하고 다시 이어갈 때, 대상 해시와
   증거 연결이 유지되는 체크포인트가 가장 직접적인 도움이 된다.
2. **기능별 비교 검사:** 재구현할 입력·출력을 먼저 정하고 원본/후보의 차이를
   회귀 사례로 남기는 흐름을 추가할 가치가 있다.
3. **함수 의존성에 따른 작업 순서:** 하위 함수부터 처리하고 순환 관계·미해결
   의존성을 표시하는 계획기를 검토한다.
4. **결과 조회 효율:** 6.7.0의 retained summary와 `inspect_analysis_view`를 먼저
   활용한다. 다른 확장의 학습 기능은 동일 대상의 품질·시간·모델 비용 비교 후
   판단한다.

이번 요청에서는 공식 업데이트와 호환 수정까지 적용했다. 위 외부 프로젝트의
코드는 개인 포크에 통합하거나 별도 MCP로 설치하지 않았다. 실제 도입 시에는
현재 배포판과의 계약·세션 정리·대상 정체성 호환성부터 검증해야 한다.

## 이번 업데이트에 포함한 범위

- 기존 6.4.0 기반에서 공식 6.7.0으로 병합.
- `inspect_artifact.input_path`, 앱/설치 폴더의 직접 검사, 실제 파일 형식에 따른
  후속 분석 안내를 보존.
- 원본의 새 summary 전달 및 읽을 수 있는 plist 링크 안내와 통합.
- 실제 Android 검증 중 발견한 스크립트 오류에 대해 공식
  [23f984b1a](https://github.com/morluto/rea/commit/23f984b1a884baefc3c44e4ab697f6eff61dffb6)
  수정만 추가 반영. 런타임 전체를 미배포 main으로 올리지는 않음.
- 기존 Ghidra 12.1.4, JDK 21, JADX headless MCP 0.7.1은 새 버전의 지원 범위와
  일치하므로 유지.

기능·테스트 기록은 로컬 `_reference/update-20261023/`에 보관한다.
Windows 실기 검증과 외부 확장들의 로컬 실행 검증은 이번 조사 범위에 포함하지 않았다.
