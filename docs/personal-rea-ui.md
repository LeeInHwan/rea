# Personal REA Local Studio

파일을 고르고, 분석하고, 복원한 앱의 실행 결과까지 한 화면에서 확인하는 로컬 웹 UI입니다.

[저장소 첫 화면](../README.md) · [CLI 사용 설명서](personal-rea-start.md) · [Workbench 설계](personal-rea-workbench.md)

## 실행하기

Mac에 설치된 **Personal REA.app**을 열거나 터미널에서 `rea-ui`를 실행합니다.
기본 브라우저에 개인 접속 주소가 열립니다. 서버는 `127.0.0.1`에만 연결되며,
접속 키는 개인 상태 폴더에 저장됩니다. 일반 공개 사이트처럼 외부에 배포하지 않습니다.

소스 checkout에서 실행하려면 기존 설치 설명대로 Node/npm을 준비하고 빌드한 다음:

```sh
node personal/ui/launcher.mjs
```

`~/Applications/Personal REA.app`과 `~/.local/bin/rea-ui`는 검증된 런타임의
`personal/ui/install.mjs`로 설치합니다. 이 설치기는 분석 엔진이나 .NET 도구를 내려받지 않습니다.
`~/.local/share/rea-personal/current`가 빌드·검사를 통과한 런타임을 가리키고 있어야 합니다.

## 1. 파일 또는 폴더 선택

**내 컴퓨터에서 찾아보기**를 눌러 앱, 실행 파일, DMG, APK 또는 설치 폴더를 고릅니다.
폴더를 누르면 내부로 이동하고, **현재 폴더 선택**으로 해당 폴더 자체를 선택합니다.
숨김 폴더는 경로 입력란에 절대 경로를 넣어 이동할 수 있습니다.

프로젝트는 원본 밖의 새 폴더에 생성합니다. **새 프로젝트**는 새 저장 경로를 채웁니다.
기존 프로젝트는 경로를 선택하고 **기존 프로젝트 열기**를 누릅니다.
원본이 바뀌면 재개를 거부하며, 기존 기록을 덮어쓰지 않습니다.

**원본 분석 시작**은 파일 구성과 해시를 보관합니다. 대상 프로그램을 실행하지 않습니다. 결과에는 구성 요소의 경로·파일 형식·해시 상태가 표시됩니다.
화면은 처음 200개 항목을 표시하고 전체 개수와 원본 Evidence 위치를 함께 보존합니다.

## 2. 복원과 빌드

현재 복원 경로는 **단일 .NET 실행 어셈블리와 내장 리소스**입니다.
등록한 원본 안의 DLL을 선택하고 새로운 복원 결과 폴더를 지정합니다.
**도구 설정**에서 ILSpy 11.1.0.9782와 호환 .NET SDK의 실행 파일 절대 경로를 지정합니다.

**소스 복원 후 빌드**를 누르면 다음이 생성됩니다.

| 위치                                             | 내용                                      |
| ------------------------------------------------ | ----------------------------------------- |
| `input/`                                         | 선택한 입력 DLL의 복사본                  |
| `source/`                                        | 복원한 C# 프로젝트와 리소스               |
| `rebuilt/`                                       | 빌드한 실행 결과물                        |
| `recovery.json`                                  | 도구·입력·출력 해시, 단계 기록, 실패 이유 |
| `*-version.json`, `decompile.json`, `build.json` | 실제 도구 실행 로그                       |

ILSpy가 선택한 .NET SDK의 표준 런타임 라이브러리를 HintPath로 기록하면,
실제 경로와 파일 해시를 확인해 SDK 기본 참조로 정리합니다. 이 변환을 receipt에 기록하며,
원본 앱의 외부 DLL·임의 빌드 작업 참조는 계속 거부합니다.

**빌드 성공만으로 앱의 동작이 같다고 판정하지 않습니다.**

## 3. 실행하고 비교하기

Mac/Linux에서 원본과 후보 실행 파일, JSON 인자 배열, 공통 작업 폴더를 지정합니다.
.NET 앱은 **선택한 .NET 앱으로 실행 경로 채우기**를 누르면 dotnet과 DLL 경로가 채워집니다.
필요한 입력 인자를 뒤에 추가하세요. 예: `["/absolute/path/Example.dll", "12", "30"]`.

실행 확인을 선택하고 **원본 ↔ 후보 실행 비교**를 누릅니다.
선택한 프로그램은 사용자 권한으로 실제 실행됩니다. 파일·네트워크 접근을 막는 샌드박스가 아닙니다.
UI가 임의의 셸 명령 문자열을 실행하는 방식은 아니며, 실행 파일과 인자 배열을 분리해 전달합니다.

결과는 두 가지를 구분합니다.

- **출력·종료 요약:** 수집된 터미널 출력 바이트와 종료 코드·사유의 비교입니다.
  출력이 잘린 경우 일치로 표시하지 않습니다. 프레임의 시간·분할 정보는 이 요약에서 제외합니다.
- **REA 전체 비교:** 터미널 프레임 시각, 프로세스 정착, 정리 상태 등 기존 REA의 비교를 그대로 보여 줍니다.
  출력이 같아도 실행 시각 차이와 관찰 한계 때문에 `changed` 또는 `unknown`일 수 있습니다.

일치 여부는 선택한 한 실행 사례에 한정합니다. 화면 버튼, 설치·업데이트, 모든 입력,
네트워크 동작의 동등성을 자동 보증하지 않습니다. Windows의 터미널 캡처는 아직 지원하지 않으며,
기존 WinForms UI 검증은 별도 Windows CI에서 수행합니다.

## 4. 전체 과정과 작업 기록

필요한 경로를 모두 지정하면 **전체 과정 실행**이 분석 → 복원·빌드 → 실행 비교를 이어서 수행합니다.
첫 실패에서 멈추고 완료된 단계와 로그를 보존합니다. 실행 중 **작업 취소**로 취소를 요청하면
소유한 프로세스의 정리 처리가 끝날 때까지 취소 중 상태가 표시됩니다.

작업과 설정은 기본적으로 `~/.local/share/rea-personal/ui/` 아래에 저장됩니다.

- `projects/`: UI가 제안하는 프로젝트와 복원 결과 경로
- `jobs/<id>/`: 작업 상태, 단계별 JSON, 원본·후보 캡처와 canonical Evidence bundle
- `settings.json`: 지정한 ILSpy·dotnet 경로
- `connection.json`: 개인 접속 주소. 공유하지 마세요.

브라우저를 닫아도 실행 중인 작업과 서버는 계속됩니다. 앱을 다시 열면 같은 서버로 접속합니다.
서버가 중단되면 미완료 작업은 다음 실행 시 **중단됨**으로 표시됩니다. 자동 재실행하지 않습니다.
**최근 작업**에서 기록을 열고 **결과 JSON 저장**으로 작업 보고서를 내려받을 수 있습니다.
프로젝트 export와 UI 실행 캡처는 별도 저장소이므로, 전체 근거를 전달하려면 해당 작업 폴더도 함께 보관하세요.

## 검증

```sh
node --test personal/ui/server.test.mjs personal/workbench/managed-restore.test.mjs
```

HTTP 인증·출처 검사, 실제 프로젝트 생성과 재개, 중복 생성 거부, 단일 작업 실행,
취소 전달, SDK 참조 경계를 검사합니다. 전체 복원·실행 검증은 준비한 도구를 명시해 실행합니다.

```sh
node personal/ui/managed-proof.mjs /absolute/path/dotnet /absolute/path/ilspycmd /absolute/path/new-proof
```

이 검사는 저장소 소유 콘솔 앱을 빌드해 DLL만 복원하고, 실제 출력과 종료 코드를 비교하며,
다른 입력의 차이를 검출하고, 원본 폴더가 없는 상태에서도 후보가 실행되는지 확인합니다.
공식 stable 버전 업데이트의 격리 검증 단계에도 UI의 기본 HTTP 검사를 포함합니다.
