# 네이티브 C/C++ 소스 재구성

Local Studio의 **네이티브 소스 복원** 카드는 macOS/Linux CLI 실행 파일을 대상으로 합니다. 원래 소스를 되찾는 기능이 아니라, Ghidra가 식별한 내부 함수의 디컴파일 결과로 실행 가능한 C/C++ 후보를 생성하고 관찰 결과를 비교하는 실험 기능입니다. GUI 앱 전체, 드라이버, 외부 라이브러리 의존성과 모든 입력의 동등성을 보장하지 않습니다.

## 화면에서 실행하기

1. 실행 파일을 분석하여 프로젝트를 만듭니다. 앱 폴더를 등록했다면 그 안의 실행 파일을 선택합니다. DMG에서 추출한 앱은 새 프로젝트로 등록합니다.
2. 결과 저장 위치는 아직 없는 폴더를 지정합니다. 도구 설정에 C/C++ 컴파일러와 로그인된 Codex CLI의 절대 경로를 넣습니다.
3. 공통 작업 폴더와 입력 사례를 지정합니다. 예: `[{"name":"도움말","args":["--help"]}]`.
4. 원본·후보 실행, 분석 결과 모델 전송을 각각 확인하고 복원을 시작합니다.
5. 생성 소스, 빌드 로그, 함수 대응, 미확인 사항과 사례별 출력·종료 결과를 확인합니다.

Codex는 사용자 설정을 읽지 않는 일회성 읽기 전용 세션으로 실행하며 셸·앱·하위 에이전트 도구를 비활성화합니다. 응답은 구조화된 소스 JSON으로 받고, 별도 파일 검증 후 지정한 컴파일러로 빌드합니다. 기존 로그인은 사용하지만 인증 정보를 읽거나 복사하지 않습니다. 도구는 자동 설치하지 않습니다. 모델 이용 비용은 사용 중인 Codex 계정 조건을 따릅니다.

## 기록과 판정

`native-recovery.json`에는 원본·도구·생성 소스·후보의 해시, 각 시도의 결과가 남습니다. `analysis/evidence.json`은 정적 분석의 canonical Evidence, `captures/evidence.json`은 실행 관찰의 canonical Evidence입니다. `attempt-N`의 모델 응답과 빌드 명령·출력은 성공 여부와 관계없이 보존합니다.

- `verified`: 식별한 내부 함수의 대응에 누락·신고된 미확인 사항이 없고 지정한 모든 CLI 사례의 출력 바이트와 정상 수집된 종료 결과가 일치합니다. 해당 유한 사례에 한정한 판정입니다.
- `behavior-mismatch`: 빌드되었지만 관찰 결과가 다릅니다.
- `build-failed`: 후보를 빌드하지 못했습니다.
- `needs-review`: 디컴파일 누락, 대응 누락, 미확인 사항 또는 모델 입력 한도 초과입니다.
- `failed` / `cancelled`: 도구 오류 또는 사용자 취소입니다. receipt에 이유가 남습니다.

프레임 시각과 분할을 포함한 canonical 비교도 별도 보존합니다. macOS에서는 컴파일·링크·후보 실행 중 등록 원본과 분석 사본의 읽기·실행을 차단하고, 실제 접근 거부도 사전 확인합니다. 다른 복사본과 외부 서비스 의존성은 별도 검증 대상입니다. Linux는 해당 차단 검증이 없으므로 `needs-review`로 남깁니다. 실패·취소 전 마지막 canonical 체크포인트도 보존합니다.

후보 수정에 사용한 사례는 독립 검증 사례가 아닙니다. 새 입력, 실제 파일·네트워크 상태, GUI 동작은 별도 검증해야 합니다. 식별된 함수 수는 전체 프로그램 복원율이 아닙니다. 입력이 120 KiB를 초과하면 몰래 잘라내지 않고 전체 분석 결과를 남긴 채 검토 상태로 종료합니다.

## 실제 제공자 검증

`personal/ui/native-proof.mjs NEW_DIRECTORY`는 저장소 소유 C 프로그램을 컴파일하고, 바이너리만 복원 흐름에 전달합니다. 정수 분기·문자열·오류 입력을 검사하고, 모델에 주지 않은 추가 사례와 원본 폴더를 치운 뒤 독립 실행을 확인합니다. Ghidra, Java, clang/clang++, 로그인된 Codex가 필요하며 일반 단위 검사에서 모델을 호출하지 않습니다.
