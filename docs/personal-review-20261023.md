## 수정한 결함

1. 원본 경로를 무관한 명령의 인자로 덧붙여도 실행 검증이 받아들였다.
   이제 원본 바인딩 경로·해시·실행 방식을 결과에 보존한다. .NET은 명시한
   dotnet 호스트와 첫 번째 절대 DLL 인자로 제한한다.
2. 종료 시 작업 소유권을 HTTP 요청보다 먼저 해제했다. 늦은 설정 요청이
   새 서버의 설정을 덮어쓸 수 있었다. 본문 이후에도 종료 상태를 확인하고
   모든 HTTP 요청과 작업 정리가 끝난 뒤 잠금을 해제한다.
3. Android 설치·정리 미확정 상태에서도 기기 lease를 해제했다.
   이제 `cleanup-unresolved` receipt와 정확한 lease를 보존해 재사용을 막는다.
4. 복원 프로젝트의 `safe.cs;/foreign.cs`, Windows 절대 경로 및 퍼센트로
   인코딩한 상위·절대 경로가 검사기를 통과했다. MSBuild 항목 목록과 문자
   이스케이프를 해석한 뒤 각 항목·속성을 검사한다.
5. qualification 중 바뀐 런타임을 새 후보가 덮어썼다. 사용자 선택이 바뀌면
   main 승격을 중단하고, 전환 직전에도 다시 확인한다. 일반 파일도 보존한다.
6. 함수 대응의 구현 설명이 비어 있어도 누락 없는 대응으로 인정했다.
   공백뿐인 설명을 포함해 잘못된 모델 응답으로 거부한다.
7. APK 실행 검증에 상대 작업 폴더를 전달하면 자식 명령이 스냅샷 경로를
   잘못 해석했다. 결과 폴더와 receipt 경로는 작업 폴더의 실제 절대 경로로 만든다.

## 검증과 해석

회귀 검사는 `personal/ui/review10.test.mjs` 및 기존 Android·native·managed·update
검사에 포함하며 개인 Workbench CI와 자동 업데이트 qualification에서 실행한다.
빌드·실제 MCP/CLI·관련 소스 검사·정적 검사·문서 검사는 별도 gate다.
Windows의 실제 EXE/.NET 복원·GUI 비교는 Windows 전용 CI가 담당한다.

실제 Android 서명·설치·지정 화면 비교·취소 정리와 네이티브 복원·별도 입력
비교는 opt-in proof로 기록한다. 에뮬레이터의 미확정 설치를 의도적으로 만드는
실험은 하지 않는다. 미확정 정리의 lease 보존 검사는 실제 파일 소유권 경계의
회귀 검사이며 실제 ADB 실패를 재현했다는 뜻이 아니다.

네이티브 모델 재생 proof는 이전에 얻은 실제 모델 응답을 재사용한다. 새 모델
생성 품질을 주장하지 않는다. 함수 대응 형식 검사도 개별 함수의 의미적 완전성
증명은 아니다. 최종 실행 receipt·CI 상태·설치 커밋은 전달 시 별도로 확인한다.

통과 범위는 감독하의 사내 샘플 파일럿이다. 범용 GUI 앱 전체 복원, 원본 소스의
정확한 재현 또는 모든 입력·네트워크·권한 조건에서의 동등성을 보장하지 않는다.
